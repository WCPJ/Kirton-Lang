# Kirton 1.1: практическое руководство

**Автор: WorldCraft Studio**<br>
Учебник для начинающих и справочный маршрут по возможностям SDK 1.1.0.

Это руководство описывает существующий интерпретатор и его стандартные модули.
Блоки в новых программах пишутся в `{}`; точки с запятой не требуются. Каждый
пример, который предполагается запускать целиком, входит в проверяемый набор
`tests/handbook_examples.kir`; фрагменты, требующие окна, сети или системных
ресурсов, отмечены отдельно. Точная таблица синтаксиса и API находится в
[`TECHNICAL_REFERENCE_V1_1.md`](TECHNICAL_REFERENCE_V1_1.md).

## Часть 1. Знакомство, установка и первая программа

Kirton — интерпретируемый язык со словами языка на русском, UTF-8 строками,
функциями, коллекциями, модулями и нативными библиотеками. Вы пишете текстовый
файл `.kir`, затем передаёте его интерпретатору.

В Windows распакуйте `Kirton-SDK-1.1.0-windows-x64.zip` или запустите графический
установщик. В терминале проверьте `kirton --version`; команда должна вывести
`Kirton 1.1.0`. Для исходной сборки нужны CMake и C11-компилятор. Текущая
квалифицированная платформа — Windows x64/MSVC; другие платформы имеют
ограничения из справки SDK.

Создайте `hello.kir`:

<!-- expect: Привет, мир! -->
```kirton
печатать("Привет, мир!")
```

Запустите `kirton hello.kir`. `печатать` — встроенная функция вывода. UTF-8
позволяет писать кириллицу как в коде, так и в строках.

## Часть 2. Переменные, типы и выражения

`пусть` создаёт имя в текущей области. Присваивание существующему имени пишется
без `пусть`:

<!-- expect: Аня\s+4 -->
```kirton
пусть имя = "Аня"
пусть счет = 3
счет = счет + 1
печатать(имя, счет)
```

Основные значения: `пусто`, `истина`/`ложь`, целые произвольной точности,
вещественные числа, строки, списки, словари, структуры и enum-значения. Тип
`целое` сохраняет большую точность, чем машинное 64-битное целое; `/` возвращает
вещественное число, `нацело` делит с округлением вниз, `%` возвращает остаток.
Операторы `+ - * / %`, сравнения, `и`, `или`, `не` и побитовые операторы
вычисляются согласно таблице приоритетов в техническом справочнике.

Условия в выражениях используют `и`/`или` с коротким замыканием: правая часть
`и` не выполняется, если левая ложна. Ложными являются `ложь`, `пусто`, ноль,
пустая строка и пустые коллекции. Проверяйте деление на ноль: это runtime-ошибка.

**Задание.** Вычислите цену трёх предметов по 125 и добавьте доставку 80.
**Решение:**

<!-- expect: 455 -->
```kirton
пусть цена = 125
пусть итог = цена * 3 + 80
печатать(итог)
```

## Часть 3. Условия и циклы

<!-- expect: Привет\s+Аня -->
```kirton
пусть температура = 21
если температура > 20 {
    печатать("тепло")
} иначе {
    печатать("прохладно")
}

пусть шаг = 0
пока шаг < 3 {
    печатать(шаг)
    шаг = шаг + 1
}

для каждого имя в ["Аня", "Илья"] {
    печатать("Привет", имя)
}
```

`прервать` завершает ближайший цикл, `продолжить` начинает следующую итерацию.
Они должны находиться внутри цикла той же функции. `для каждого` перебирает
списки, строки и поддерживаемые типизированные массивы. Не изменяйте длину
списка неожиданно: добавленный в конец элемент может попасть в текущий обход.

**Задание:** сложить числа от 1 до 5. **Решение:** завести сумму и счётчик,
пока счётчик не больше 5 прибавлять его к сумме, затем увеличить счётчик.

## Часть 4. Функции, рекурсия и замыкания

<!-- expect: 12\s+120 -->
```kirton
функция удвоить(число) {
    вернуть число * 2
}

функция факториал(n) {
    если n <= 1 {
        вернуть 1
    }
    вернуть n * факториал(n - 1)
}

печатать(удвоить(6), факториал(5))
```

Аргументы позиционные, их число должно совпадать с параметрами. Функция без
`вернуть` возвращает `пусто`. Рекурсивные и взаимно рекурсивные объявления
доступны внутри окружения функции. Вложенная функция захватывает окружение по
ссылке: она видит последующие присваивания захваченной переменной. Параметры и
локальные переменные доступны до конца соответствующей функции; блоки условий
и циклов не создают отдельного окружения. Объявление `пусть` внутри функции
локально для этого функционального окружения.

Избегайте глубокой рекурсии для длинных последовательностей: гарантии
оптимизации хвостовых вызовов нет.

## Часть 5. Строки, коллекции и пользовательские типы

Строки неизменяемы; индекс начинается с нуля и измеряется в Unicode-кодпоинтах.
Списки записываются через `[...]`, словари — через `{строковый_ключ: значение}`:

<!-- expect: прочитать\s+Киртон -->
```kirton
пусть задачи = ["прочитать", "проверить"]
пусть карточка = {"имя": "Киртон", "версия": 1}
печатать(задачи[0], карточка["имя"])
```

Словарь — выражение. `{` после заголовка функции, условия, цикла, обработки
ошибок или типа открывает блок. Для значения структуры используйте конструктор:

<!-- expect: EXIT_SUCCESS -->
```kirton
структура Игрок {
    имя: строка
    здоровье: целое
}
перечисление Состояние {
    ожидание
    активно
}
пусть игрок = Игрок(имя: "Ада", здоровье: 100)
пусть режим = Состояние.активно
```

Поля структуры объявляются как `имя: тип`; enum перечисляет варианты. Enum-
значения разных типов не равны друг другу. Вложенные списки/словари динамичны;
аннотации полей пользовательского типа проверяются при создании и присваивании.

## Часть 6. Модули и проекты

`импорт` подключает модуль по имени. Имя с точками отображается в путь каталогов
и файл `.кир`; `импорт "путь"` задаёт путь явно, `как` вводит псевдоним.
Разрешение ищет относительно импортирующего файла, рабочего каталога и
`KIRTON_PATH`. Повторный импорт одного модуля в VM не должен повторно выполнять
его инициализацию.

<!-- expect: Мир готов -->
```kirton
импорт "examples.lib.мир" как мир
мир.инициализировать()
```

Держите приложение в `main.kir`, повторно используемый код — в отдельном модуле,
а тестовые скрипты — рядом в каталоге `tests`. Путь к модулю учитывает
кодировку и правила платформы; используйте UTF-8.

## Часть 7. Исключения

<!-- expect: операция завершена -->
```kirton
попробовать {
    пусть текст = фс_прочитать_текст("данные.json")
    печатать(текст)
} перехватить ошибка {
    печатать("Ошибка:", ошибка.сообщение)
} всегда {
    печатать("операция завершена")
}
```

Нативная или вычислительная runtime-ошибка передаёт управление ближайшему
`перехватить`. Объект ошибки содержит диагностические сведения, включая код,
сообщение, файл и место возникновения. `всегда` выполняется при обычном выходе,
ошибке и раннем `вернуть`; ошибка из `всегда` может заменить исходный исход.
Синтаксические ошибки обнаруживаются до выполнения и этим блоком не ловятся.

## Часть 8. Память и ресурсы

Обычные строки, списки, словари, большие целые и объекты VM управляются
трассирующим сборщиком мусора. GC находит достижимые объекты от корней VM и
освобождает недостижимые; не требуется вручную удалять каждый список.
Сохранённые C-ссылки на значения нужно закреплять публичным API VM до следующего
цикла сборки.

Модуль `память` предоставляет явные области, byte-буферы, записи и типизированные
массивы. Область резервирует backing storage; её дескриптор остаётся объектом
VM. Вызовы требуют проверки ошибок, границ, выравнивания, поколения/свежести и
порядка владения. Borrow-токен и lease ресурса ограничивают время действия
указателя; не сохраняйте его после завершения borrow. `vm_try_free` может
отказать, пока активны заимствования. Нативные ресурсы закрывайте явно либо
передавайте владение API VM согласно контракту.

Подробные сценарии и ограничения см. в `MEMORY_V2_1.md`–`MEMORY_V2_8.md` и
`NATIVE_RESOURCE_AUDIT.md`; эти документы относятся к реализации SDK и не
добавляют синтаксис языка.

## Часть 9. Файлы, JSON, regex и сеть

Файловые глобальные функции используют префикс `фс_`, например
`фс_прочитать_текст` и соответствующую функцию записи; пути передавайте строками
и обрабатывайте ошибку. Глобальные функции JSON: `json_прочитать`,
`json_валиден`, `json_написать` (также есть совместимые псевдонимы
`json_разобрать`/`json_собрать`). Сериализуемые словари используют строковые
ключи. NaN/бесконечность не являются допустимым JSON-числом.

Глобальные функции `регэксп_*` предоставляют проверку, поиск, замену и разбиение; индексы
регулярных выражений документированы как byte offsets, что отличается от
Unicode-индексов строк. Глобальные функции `http_*` предоставляют HTTP-запросы
в Windows через WinHTTP; POSIX HTTP в текущей версии не поддержан. Сетевые вызовы могут
блокироваться и завершаться ошибкой; задавайте таймауты, когда API их принимает,
и не считайте внешнюю сеть доступной в тестах.

## Часть 10. Графика и игровые циклы

Графические API доступны в Windows SDK и зависят от драйвера и окна. `gl` —
модуль OpenGL; примеры показывают создание окна, опрос событий, клавиатуру,
очистку буфера, шейдеры, буферы вершин и swap. В примере Pong из
`examples/apps/gl_test_d_pong.kir` игровая логика обновляет координаты и
отражает скорость от границ, а кадр рисуется через compatibility API.

Не запускайте вычислительно тяжёлую работу в каждом кадре. Считывайте ввод,
обновляйте состояние с ограниченным шагом, очищайте/рисуйте кадр и обрабатывайте
закрытие окна. Для GPU-ресурсов соблюдайте порядок создания и освобождения.
Headless CTest не подтверждает визуальное качество, GPU-драйвер или ввод на
каждой машине; интерактивные демонстрации проверяются отдельно на Windows.

## Часть 11. C/C++ и FFI

Встраиваемый API доступен в `include/kirton/eval.h`: создайте `VM*` через
`vm_new`, выполните файл через `vm_run_root`, затем освободите VM. Проверяйте
ошибки создания/выполнения и результат `vm_try_free`. Значения, принадлежащие
VM, нельзя использовать после её освобождения.

`kirton_core` — статическая библиотека; исходный C API экспериментальный и не
обещает стабильную ABI или версионирование символов. Собирайте host с заголовками
того же SDK и платформенными зависимостями из CMake. FFI позволяет загружать
нативные библиотеки в процесс и выключен по умолчанию. Разрешайте его только для
доверенного кода флагом `--allow-ffi`; ошибка ABI или недоверенный модуль может
повредить процесс.

## Часть 12. Производительность и практические проекты

Сначала измерьте время на реалистичном вводе. Сокращайте повторное чтение и
создание временных коллекций в горячем цикле; не вводите вручную память без
профиля. Простой тайминг можно сделать модулем `время`/`таймеры`, сравнивая
несколько запусков на одном вводе. В текущем SDK нет встроенного sampling-
профайлера, JIT или компилятора.

Практический проект: трекер задач из `examples/apps/task_tracker.kir`. Изучите
модель данных, операции над списком, вывод и обработку ошибочных входных данных.
Затем добавьте фильтрацию и тесты к чистым функциям; не меняйте формат хранения
без отдельной миграции.

**Задание:** вынести подсчёт незавершённых задач в функцию и проверить на пустом
списке, одной завершённой и одной активной задаче. Решение: функция проходит по
списку, увеличивает локальный счётчик для незавершённых записей и возвращает
его. В репозитории смотрите готовые операции модели в `examples/apps/task_model.kir`.

## Часть 13. Синтаксис и стандартные библиотеки

Формальная спецификация грамматики 1.1 и различения словарей/блоков приведена
в `SYNTAX_V1_1.md`. Точный операторный приоритет, токены, CLI, модули и
ограничения перечислены в `TECHNICAL_REFERENCE_V1_1.md`. Реально существующие
стандартные поверхности включают файловые `фс_*`, `память`, `json_*`, `регэксп_*`, `http_*`,
`время`, `таймеры`, `математика`, `строка`, `списки`, `словарь`, `путь`, `процесс`,
`операционная_система`, `gl` и Windows графические модули. Имена и сигнатуры
следует сверять со справочником и объявлениями модулей исходного SDK.

### Совместимость с 1.0

Программы со словом `конец` продолжают работать. Для новых блоков используйте
парные скобки; нельзя закрывать одним блоком `конец`, если он открылся через `{`.
Внутри файла можно вкладывать блоки двух поколений, но не смешивать закрыватели
одной конструкции. `то` остаётся допустимым в старом стиле и необязателен в новом.
Регулярная замена опасна для вложенных блоков и строк: мигрируйте по уровням и
запускайте тесты.
