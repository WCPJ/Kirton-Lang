# Синтаксис Kirton 1.1

Kirton 1.1 сохраняет семантику языка и совместимость с программами Kirton 1.0.
Фигурные блоки — основной рекомендуемый стиль; блоки, закрываемые словом
`конец`, продолжают поддерживаться как legacy-синтаксис без объявленной даты
удаления. Нормативный контракт и поведение 1.0 описаны отдельно в
[`SYNTAX_V1.md`](SYNTAX_V1.md).

## Блоки

```kirton
функция сумма(a, b) {
    если a > b {
        вернуть a + b
    } иначе {
        вернуть b - a
    }
}

пока условие {
    печатать("ещё")
}

для каждого элемент в список {
    печатать(элемент)
}
```

Фигурные блоки применимы к функциям, `если`/`иначе`, `пока`, `для каждого`,
обработке ошибок (`попробовать`/`перехватить`/`всегда`), структурам и
перечислениям. В условных и циклических конструкциях `то` необязательно;
канонический фигурный стиль его не использует. Точка с запятой не нужна.

Для каждого блока способ закрытия определяется его открытием: `{` закрывается
парной `}`, а legacy-блок без `{` закрывается `конец`. Смешивать эти два способа
в одном блоке нельзя. Старые и новые блоки можно вкладывать друг в друга.
В `если` с `иначе` обе ветви используют один стиль. В новом стиле каждая ветвь
имеет собственные скобки.

## Ошибки и пользовательские типы

```kirton
попробовать {
    пусть значение = 1 нацело 0
} перехватить ошибка {
    печатать(ошибка.сообщение)
} всегда {
    печатать("завершено")
}

структура Игрок {
    имя: строка
    здоровье: целое
}

перечисление Состояние {
    ожидание
    активно
}
```

Секции обработки ошибок используют скобки в новом стиле. Для `перехватить`
нужно имя переменной ошибки. `всегда` необязателен, если есть `перехватить`, и
наоборот.

## Фигурные скобки в выражениях

Парсер определяет назначение `{}` по контексту:

- Сразу после заголовка функции, условия, цикла, блока обработки ошибок или
  объявления структуры/перечисления `{` начинает блок.
- В позиции выражения `{ключ: значение}` создаёт словарь. Ключи словарей —
  строки. Например: `пусть карточка = {"имя": "Киртон"}`.
- Для создания значения структуры по-прежнему используется вызов конструктора,
  например `Игрок(имя: "Ада", здоровье: 100)`. Литерал структуры через `{}` не
  вводится.

## Форматирование

Ставьте открывающую `{` в конце строки заголовка, закрывающую `}` — на отдельной
строке с отступом уровня заголовка. Между закрытием ветви и `иначе` используйте
`} иначе {` на одной строке. Вложенные блоки отступают на четыре пробела. Не
добавляйте обязательные `;`.

```kirton
если готово {
    печатать("да")
} иначе {
    печатать("нет")
}
```

## Переход с `конец`

Для механической миграции:

1. После заголовка `функция`, `если`, `иначе`, `пока`, `для каждого`,
   `попробовать`, `перехватить`, `всегда`, `структура` или `перечисление`
   замените переход к следующей строке тела открывающей `{`.
2. Замените соответствующий `конец` на `}`. В `если`/`иначе` закройте каждую
   ветвь отдельно: `} иначе {`.
3. Удалите необязательное `то` из условия `если` или `пока`.
4. Не заменяйте слово `конец` глобально: сопоставляйте его с правильным
   вложенным блоком. Строки, комментарии и словари не меняются.
5. Проверьте вложенные блоки после преобразования.

Конвертер на уровне регулярных выражений небезопасен: блоки могут быть вложены,
а строки и комментарии могут содержать текст, похожий на синтаксис. До
появления лексически осведомлённого форматтера мигрируйте по синтаксическим
уровням.
