# Kirton — передача работы после прерывания Codex (2026-11-03)

Восстановлено из архива `kirton-c(1).zip`. Исходный архив не изменялся. Рабочие правки выполнены в исходниках и тестах этого пакета; каталоги `build/` и `build_tmp/` из исходного архива не включены в выдаваемый архив, чтобы избежать устаревших Windows build-artifacts.

### Что именно изменено

- `src/eval.c`: включён per-VM tracing GC, root-stack в выражениях и операторах, защита значений и окружений вызовов; освобождение обычных call frames; API для pin/unpin, ручной сборки, счётчиков, `vm_free`; ownership AST, загруженных VM; временное отключение bigint heap во время парсинга AST.
- `src/ast.c`, `include/kirton/ast.h`, `src/parser.c`: полная функция удаления AST и устранение AST-утечек при присваиваниях.
- `include/kirton/eval.h`: публичный жизненный цикл VM и контракт закрепления внешних значений.
- `src/main.c`: освобождение AST и массива `lang_argv`; Linux корректно пропускает Windows-only `clipboard_init`.
- `CMakeLists.txt`: Linux линковка `libm`, добавлен CTest на работу GC.
- `tests/gc_runtime.c`, `tests/gc_runtime.kir`: новый стресс-тест сборки/закрепления/циклов.
- `tests/vm_isolation.c`: явный вызов `vm_free` после проверки двух независимых VM.
- `docs/MEMORY_DESIGN.md`: зафиксированы возможности, недостатки и следующее направление.

### Проверка

Release/Linux (GCC): 32/32 теста. Sanitizers/Linux (`-fsanitize=address,undefined`): 32/32 теста. Отдельные проверки GC и изоляции прошли LeakSanitizer.

Нельзя утверждать, что память готова к V1, пока не закрыты перечисленные в `MEMORY_DESIGN.md` ограничения и не проведены Windows/MSVC-тесты.

### Следующее продолжение: Memory System V2 (preview)

- Добавлены `VAL_ARENA`/`VAL_BUFFER` и GC-трассировка дочернего буфера к родительской арене.
- Модуль языка `импорт память` — создание/выделение/чтение/запись/сброс/закрытие, нулевая инициализация повторных выделений, контроль выравнивания реального базового адреса.
- Контроль VM: `vm_memory_arena_bytes`, `vm_memory_set_arena_limit`, байтовый порог GC для резервирований арен.
- Запрет передачи прямых arena/buffer handles между VM и сериализации в JSON; тесты на UAF, GC pin и вложенные объекты, а также регрессия утечек в тестовых C-клиентах.
- Полный контракт и незакрытые работы: `docs/MEMORY_V2.md`.
