# Kirton 1.0 — конечный release gate

## Решение о контракте

Семантика 1.0 зафиксирована текстом [`SYNTAX_V1.md`](SYNTAX_V1.md). В этом
release gate нет изменений правил языка ради текущего поведения интерпретатора.
Покрытие и доказательства сопоставлены в [`CONFORMANCE_V1.md`](CONFORMANCE_V1.md).
Исправление реализации допустимо только для соответствия этой спецификации.
Если обнаружится противоречие самой спецификации, оно оформляется отдельным
обоснованным изменением контракта и не маскируется правкой теста.

## Обязательные условия выпуска

Все условия обязательны; отсутствие инструмента или результата означает
`BLOCKED`, а не успешное прохождение.

| Gate | Критерий | Доказательство |
|---|---|---|
| G-01 | В `SYNTAX_V1.md` заморожен публичный контракт; у каждого требования есть строка матрицы и проверка | `SYNTAX_V1.md`, `CONFORMANCE_V1.md`; этот документ фиксирует решение о заморозке |
| G-02 | Нет подтверждённых дефектов уровня blocker; все обязательные language/API/CLI conformance cases проходят | Полный CTest Release из тестовой сборки: `ctest --test-dir build-release-test -C Release --output-on-failure` |
| G-03 | Производственная конфигурация компилируется без test allocator hooks | Release configure/build с `BUILD_TESTING=OFF`; конфигурация зафиксирована CMake cache |
| G-04 | Установленный пакет содержит интерпретатор, руководство, спецификацию, платформенную и conformance документацию и запускает два многофайловых примера | Проверить install tree: `kirton.exe --help`, task tracker и expense report из установленной папки examples |
| G-05 | Все заявленные платформы прошли G-02—G-04 | Для 1.0 заявлена только Windows x64/MSVC; исторические и заблокированные прогоны не добавляются в список поддержки |
| G-06 | Известные ограничения опубликованы вместе с поддерживаемой платформой | `PLATFORMS_V1.md`, раздел «Ограничения» ниже |

## Решения по охвату 1.0

| Область | Классификация | Обоснование / условие |
|---|---|---|
| Windows x64/MSVC, язык, CLI, core API и перечисленные FFI/memory contracts | Обязательно для 1.0 | Только эта платформа включена в заявление поддержки; точные тесты перечислены в conformance-матрице |
| Linux/GCC | Не входит в поддержку 1.0; повторный прогон — кандидат для 1.0.1 | **BLOCKED** в текущем workspace: нет доступного GCC/Clang/Linux toolchain. Имеется только исторический результат 64 тестов без записанных версии GCC и архитектуры |
| Coverage-guided libFuzzer | 1.0.1 hardening | Harness и deterministic malformed-input tests имеются; Clang/libFuzzer прогон не подтверждён. Отсутствие такого прогона само по себе не означает, что обнаружен дефект |
| Дополнительные OOM injection точки в остальных native modules | 1.0.1 hardening, если не выявлен дефект | Текущие детерминированные проверки покрывают перечисленные core modules; полного fault-injection покрытия каждого optional/legacy native module нет |
| Внешние HTTP endpoints, GPU/async driver, ручные GUI/audio сценарии | 1.0.1 validation расширений | Локальный HTTP GET/POST path покрыт `kirton_http_loopback`; внешние сервисы, GPU и устройства не входят в подтверждённую матрицу 1.0 |
| Legacy graphics/audio: изоляция таблиц ресурсов между несколькими VM; параллельная VM | 1.1+ | Текущее состояние process-global; контракт 1.0 явно ограничивает использование одной последовательно работающей VM на процесс |
| Linux POSIX process timeout/cwd и POSIX HTTP implementation | 1.1+ или отдельное расширение платформы | POSIX process options сейчас не поддерживаются, HTTP возвращает «не поддержан»; Linux не заявлен для 1.0 |
| Пакетный менеджер, JIT/LLVM, наследование, IDE, Vulkan, многопоточный GC | 1.1+ | Явно исключены из базовой языковой основы 1.0 в `SYNTAX_V1.md` |

## Результаты текущего прохода (2026-11-04)

Все обязательные gate G-01—G-06 закрыты для заявленного Windows x64/MSVC target:

- **Current SDK Release CTest:** `build-sdk-test`; 129/129 прошли, 0 ошибок. Команда:
  `ctest --test-dir build-sdk-test -C Release --output-on-failure`.
- **Release CTest inventory:** CTest зарегистрировал ровно 129 тестов, включая CLI version, embedding host, Getting Started и локальный HTTP GET/POST loopback (`kirton_http_loopback`).
- **Production Release:** сборка и установка прошли с `BUILD_TESTING=OFF` в
  `build-sdk-release` и `build-sdk-install`.
- **Пакет:** `kirton.exe --help` и `--version` завершились с кодом 0; установленный
  ZIP распакован и проверен по CLI, модульному примеру, `task_tracker.kir` и
  отдельно скомпилированному C API host из файлов SDK.
- **Платформа:** Windows x64/MSVC 14.52.37025, Windows SDK 10.0.26100.
- **Документы:** точные команды и результат обновлены в
  [`PLATFORMS_V1.md`](PLATFORMS_V1.md).
- **Другие известные проверки:** coverage-guided fuzz run отмечен `BLOCKED`
  из-за отсутствия Clang/libFuzzer и доступного WSL-дистрибутива; он
  классифицирован как 1.0.1 hardening, не как обязательный gate 1.0.

## Известные ограничения, не являющиеся блокерами по контракту 1.0

- Рекурсивный вызов одной VM и FFI не являются обещанием потокобезопасности;
  параллельные вызовы VM не поддерживаются.
- Legacy `window`, `gl`, `d3d11`, `sound` и `bitmap` используют process-global
  таблицы; безопасный заявленный сценарий — одна последовательно используемая
  VM на процесс. Реальные устройства и графические драйверы не проверены.
- HTTP body и process output ограничены 64 МиБ. Локальный HTTP GET/POST path
  проверяется loopback тестом; внешние endpoints и реальная доступность сети не
  входят в автоматический offline suite.
- POSIX process cwd/timeout и HTTP не поддерживаются. Linux не входит в список
  платформ Kirton 1.0.
- Задержанный C-кодом указатель на значение без pin/lease остаётся нарушением
  публичного API и не получает гарантий времени жизни.

## Конечная остановка

После прохождения G-01—G-06 и проверки, что в трекере нет известных blocker,
релизная стабилизация останавливается. Незаявленная платформа, неиспытанное
устройство или улучшение без подтверждённого дефекта не расширяют gate задним
числом; они получают версию по таблице выше.
