# Kirton 1.1.0 — технический справочник

**Автор: WorldCraft Studio**

Этот документ описывает контракт синтаксиса и поверхности API SDK. Точный набор
нативных функций конкретной платформы определяется собранными модулями и
заголовками/таблицами регистрации исходников; графические и FFI возможности
помечены по платформе.

## Синтаксис

Исходник UTF-8. Идентификатор начинается с `_`, латинской или кириллической
буквы; далее допустимы цифры. Комментарии: `//`, `#` до конца строки, либо
не-вложенный `/* ... */`. Строка в двойных кавычках поддерживает `\\`, `\"`,
`\n`, `\r`, `\t`.

```ebnf
program       = { declaration | statement } ;
function      = "функция" identifier "(" [ identifiers ] ")" block ;
block         = "{" { statement } "}" ;
if            = "если" expression block [ "иначе" block ] ;
while         = "пока" expression block ;
foreach       = "для" "каждого" identifier "в" expression block ;
try           = "попробовать" block
                [ "перехватить" identifier block ]
                [ "всегда" block ] ;
struct        = "структура" identifier "{" { identifier ":" type } "}" ;
enum          = "перечисление" identifier "{" { identifier } "}" ;
legacy-block  = header { statement } "конец" ;
```

В `try` необходима секция `перехватить` или `всегда`. Тела блоков разделяются
границами операторов (обычно переводами строки); `;` не обязателен. `то` можно
писать в совместимом синтаксисе `если`/`пока`, но в новом стиле его опускают.
В `иначе` каждое тело имеет собственные `{}`; формат: `} иначе {`.

В позиции выражения `{строка: значение, ...}` — словарь. После заголовка
управляющей конструкции и после имени структуры/enum `{` открывает блок. Литерал
структуры через скобки не реализован: экземпляр строится вызовом
`ИмяТипа(поле: значение)`. Отсутствие `;` не означает, что перенос строки
внутри выражения завершает его: незаконченные выражения могут продолжаться.

В одном блоке нельзя менять `{}` на `конец`. Блоки разных стилей можно вложить.
Две ветви одного `если` обязаны использовать один стиль.

## Операторы и приоритет

От высокого к низкому (операторы одного уровня левоассоциативны):

| Приоритет | Операторы |
|---:|---|
| 60 | `* / % нацело` |
| 50 | `+ -` |
| 45 | `<< >>` |
| 40 | `&` |
| 35 | `^` |
| 30 | `|` |
| 20 | `< <= > >=` |
| 15 | `== !=` |
| 10 | `и` |
| 5 | `или` |

Унарные `не`, `-`, `~` связываются сильнее бинарных. `/` даёт binary64;
`нацело` округляет вниз. Деление и остаток на ноль дают runtime-ошибку.
Целочисленные операции сохраняют точность произвольной длины. Сдвиг принимает
неотрицательное смещение, помещающееся в `int64`.

## Значения и семантика

Встроенные типы аннотаций: `пусто`, `булево`, `целое`, `число`, `строка`,
`список`, `словарь`, пользовательские структуры и enum. Списки/словари
динамические. `пусть` объявляет или переобъявляет имя в текущем окружении;
присваивание без объявления ищет существующую ближайшую привязку и ошибается,
если её нет. Блоки потока не создают собственную область видимости.

Строковый индекс — неотрицательный индекс Unicode-кодпоинта. Индексы regex
являются byte offsets. Истина определяется truthiness: ложны `ложь`, `пусто`,
числовой ноль, пустая строка, пустой список и словарь. Сравнение коллекций
выполняется по содержимому; NaN не равен себе.

## Встроенные модули и API

Модули доступны после регистрации интерпретатором; часть функций глобальная,
часть требует `импорт` по имени. Подробные определения сигнатур — в таблицах
`KirNativeDef` соответствующего `src/mod_*.c`.

| Модуль/имена | Назначение и подтверждённая поверхность |
|---|---|
| `фс_*` | Глобальные файловые функции, включая `фс_прочитать_текст`. |
| `json_*` | `json_прочитать`, `json_валиден`, `json_написать`; псевдонимы `json_разобрать`, `json_собрать`. |
| `регэксп_*` | Глобальные функции регулярных выражений; индексы результата — смещения в UTF-8-байтах. |
| `память` | Области, byte-буферы, записи, типизированные массивы; borrow/lease APIs имеют срок жизни. |
| `http_*` | Глобальные HTTP-функции через WinHTTP в Windows; POSIX реализация сообщает «не поддерживается». |
| `gl` | Оконный OpenGL Compatibility/Core API: окна, ввод, буферы, шейдеры, отрисовка. Требует Windows и графического драйвера. |
| `d3d11` | Direct3D 11; только Windows. |
| `внешний` | Загрузка и вызов FFI после явного включения `--allow-ffi`. Только доверенные библиотеки. |
| `математика`, `математика3d`, `строка`, коллекции | Глобальные функции операций над значениями; это наборы функций, не обязательно импортируемые модули. |
| `path`, `os`, `sys`, `pkg`, `память`, `ресурсы` | Модули путей, ОС, системной информации, пакетного менеджера, памяти и нативных ресурсов. |
| `gl`, `d3d11`, `math3d` | Модули графики/3D; `d3d11` только Windows, `gl` требует OpenGL. |

Набор глобальных имён и их псевдонимы также включают функции печати, типизации,
списков, строк, regex, JSON, HTTP, таймеров и FFI. Не предполагайте универсальность системных вызовов: например,
POSIX HTTP, cwd/timeout опции POSIX процесса и GPU на Linux не поддержаны.

## CLI

`kirton [опции] <файл.kir> [-- аргументы]`; `-e/--entry имя` явно вызывает
функцию после init; `-m` — совместимый псевдоним. `--allow-ffi` включает загрузку
доверенных C-библиотек; `--version`, `-h/--help` печатают сведения и завершаются.
Коды: 0 успех, 64 ошибка использования, 65 ошибка разбора, 66 файл не открыт,
70 ошибка выделения памяти. Коды runtime не являются стабильным API.

## C API и память VM

`include/kirton/eval.h` описывает `vm_new`, `vm_run_root`, `vm_free` и
`vm_try_free`, закрепление значений `vm_value_pin`/`vm_value_unpin`, borrow и
lease контракт. `kirton_core` статична. API исходный, экспериментальный, не
имеет стабильной ABI; один VM нельзя выполнять конкурентно. Значения VM
недействительны после её уничтожения. Проверьте результат создания/запуска и
результат `vm_try_free`.

## Ограничения, безопасность, версии

Windows x64/MSVC — квалифицированная платформа. POSIX возможности перечислены в
`KNOWN_LIMITATIONS.md`; оконные графика, звук, clipboard и реальные GPU требуют
проверки на целевом оборудовании. FFI работает в адресном пространстве процесса,
поэтому недоверенный код может аварийно завершить host.

Kirton 1.1.0 меняет рекомендуемый стиль блоков при сохранении `конец` ради
совместимости. Сборщик мусора, runtime и семантика операторов не менялись.
Нормативная замороженная база 1.0 хранится в `SYNTAX_V1.md`.
