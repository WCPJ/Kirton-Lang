# GC и время жизни значений Kirton

Этот документ описывает текущее владение значениями в `kirton-c`. Контракт
языка задаётся [спецификацией 1.0](SYNTAX_V1.md), а перечень проверок и
платформенный статус — [conformance-матрицей](CONFORMANCE_V1.md) и
[матрицей платформ](PLATFORMS_V1.md).

## VM и сборка мусора

- Каждая VM владеет отдельными кучами значений и больших целых. Runtime-строки,
  списки, словари, замыкания, структуры, enum-значения и нативные ресурсы
  отслеживаются своей VM. Арены, буферы, типизированные массивы и записи также
  привязаны к куче VM.
- GC отмечает корневое окружение, активные вызовы, модульный кэш, замыкания,
  временные значения и закреплённые C-значения. Коллекции обходятся итеративно,
  поэтому циклические списки и словари не вызывают бесконечной рекурсии.
- Сборка запускается на безопасных границах выполнения. `vm_gc_collect()`
  запускает её явно; `vm_gc_tracked()` и `vm_gc_collections()` дают счётчики
  для хоста и тестов.
- AST живёт отдельно от runtime GC. Программы, переданные через
  `vm_eval_program_into()`, остаются собственностью вызывающего C-кода; AST,
  разобранные самой VM, освобождаются вместе с VM.

## Контракт C API

- `vm_call_by_name()` возвращает `Value` без автоматического закрепления.
  Если результат должен пережить следующую операцию, способную запустить GC,
  закрепите его через `vm_value_pin()`.
- Закрепление и передача проверяют владение VM, включая вложенные значения.
  Управляемые строки, списки, словари, BigInt и memory handles другой VM
  отвергаются. Неуправляемые значения, включая созданные C-кодом или оставшиеся
  в собственности AST-литералы, остаются ответственностью вызывающей стороны.
- `vm_value_pin()` не передаёт владение. Закреплённое значение остаётся
  действительным до `vm_value_unpin()` или уничтожения владеющей VM. После
  `vm_free()` любые указатели на объекты этой VM недействительны.
- `vm_memory_borrow()` выдаёт сырой адрес только на срок жизни borrow-token.
  `vm_native_resource_lease_begin()` удерживает native resource, пока хост не
  подтвердит завершение внешней операции. Ни один из механизмов не делает
  сохранённый C-указатель безопасным после освобождения токена.

## Ограничения

- VM и GC однопоточны. Вызовы VM из параллельных потоков не поддерживаются.
- `vm_memory_arena_bytes()` считает резерв аренных хранилищ, а не полный объём
  памяти VM. Суммарный лимит байтов и паузы GC для больших нагрузок не измерены.
- Произвольные нативные расширения доверенные: сырые C-указатели и callback-код
  могут нарушить контракт времени жизни и повредить процесс.
- Часть графических и аудиомодулей использует process-global состояние и не
  изолирована между VM. Эти биндинги не входят в ядро conformance 1.0.
- Сборка и полный тестовый набор проверены для Windows x64/MSVC. Актуальный
  Linux-прогон отсутствует; см. матрицу платформ перед обещанием поддержки.

## Проверки

GC, pinning, изоляция VM, арены, borrowing и native leases проверяются тестами
`gc_runtime`, `gc_pin_values`, `vm_isolation` и `memory_v2_*`. Полный текущий
набор нужно запускать командами из `GETTING_STARTED_V1.md`; фактические результаты
по платформам отражаются в `PLATFORMS_V1.md`.
