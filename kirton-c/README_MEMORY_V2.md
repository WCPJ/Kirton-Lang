# Kirton — Memory System V2.1 (экспериментальная реализация)

Исходный язык и интерпретатор продолжают работать как прежде. По умолчанию
строки, списки, словари и большие целые управляются GC. По явному запросу
разработчик может создать арену и разместить в ней **проверяемый байтовый
буфер или типизированный числовой массив**.

**Документация:** `docs/MEMORY_V2_1.md` (новые типизированные массивы),
`docs/MEMORY_V2.md` (первый этап), `docs/MEMORY_DESIGN.md` (GC).

**Пример:** `tests/memory_v2_typed.kir`.

```kirton
импорт память
пусть область = память.создать(4096)
пусть значения = память.массив(область, "целое32", 100)
значения[0] = 42
печатать(значения[0])
память.закрыть(область)
```

**Сборка:**

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
```

**Ограничения:** нет сырых указателей, ручного `malloc/free`, составных структур
в аренах, настоящего C ABI, полного учёта всей памяти VM, многопоточного GC.
Это не финальный Kirton 1.0. Windows/MSVC пока не проверены.
